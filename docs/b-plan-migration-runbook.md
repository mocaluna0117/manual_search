### 最大の技術リスク

管理者のチャット操作（「〇〇フォルダを作って」「△△に移動して」など6種類）は、
Bedrockの **tool use**（AIに関数を呼ばせる仕組み）に依存しています。
Workers AIのモデルで同じことができるかを最初に確認します。

できない場合の代替:
1. 明示的な命令文を決めて、AIを介さず直接実行する経路を増やす
   （既に「分類ルールを追加:」等で実装済みの方式を広げる）
2. 管理操作だけは画面のボタン・右クリックメニューで行う（機能自体は全て画面にある）

いずれもチャットからの操作が減るだけで、**機能が失われることはありません。**

## 3. もしIT管理者の対応が間に合わない場合

認証はAWS（Cognito）にあるため、**AWSが閉鎖されると全員ログインできなくなります**。
Entra IDが間に合わない場合は、次善の策として **Supabase Auth**（無料・50,000人まで）を使います。

- メールアドレスと招待でログインする、今と同じ方式
- 追加費用なし、会社への依頼も不要
- 欠点: パスワードを1つ増やすことになる（Entra IDの利点が得られない）
- 後からEntra IDへ移すことは可能

**判断の期限は9月1日**。この時点でIT管理者の作業が始まっていなければ、
Supabase Authで進めて切り替えを優先します。

## 4. 切り替え当日の手順（詳細は実装後に確定）

1. 新環境を起動し、最終のデータ移行を行う（DBとPDF）
2. 動作確認（ログイン・検索・AI回答・PDF閲覧・アップロード・管理操作）
3. 利用者へ新URLを周知
4. AWS側を `scripts/aws-stop.sh` で停止（すぐには消さない）
5. 1週間様子を見て問題なければ、最終バックアップを取ってAWSを撤収
   （手順は `docs/deployment-plan.md` の撤収手順）

## 5. 撤収前に必ずやること

- `./scripts/backup-all.sh` の最終実行と、`./scripts/verify-backup.sh` での確認
- バックアップの保管先を2か所以上にする（会社PC＋外付けドライブなど）
- Cognitoの利用者一覧を保存（パスワードは取り出せない仕様）
- `infra/` 配下の設定ファイルがGitに入っていることの確認
