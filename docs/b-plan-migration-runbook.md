## ⚠️ 最初に知っておくべき制約

**クレジットが尽きるとAWSアカウントは自動的に閉鎖され、その時点でデータに
アクセスできなくなる。** データ自体は90日間保持されるが、読み出すには有料プランへの
アップグレード（＝課金）が必要になる。

つまり「尽きてから移行を始める」ことはできない。次の2つは**枯渇前に**終わっていること。

1. 最新データの取り出し（`./scripts/backup-all.sh`）
2. 新環境が動く状態になっていること

逆に言えば、この2つが済んでいれば、あとはいつ切り替えても構わない。

### クレジットを使い切らない（重要）

**$25程度は使わずに残す。** 移行で問題が起きたとき、AWSを一時的に戻せる余地に
なる。0円まで使い切ると、その退路が無くなる。$25 ≒ 9日分の運転資金。

## 1. 木村さんにお願いしたいこと

### (a) 会社のIT管理者への依頼（8月末〜9月初に送る）

Entra ID（会社のMicrosoftアカウントでのログイン）と通知メールの送信に必要。
**追加費用はかからない**（M365の契約に含まれる機能）。以下をそのまま送れる。

依頼から実作業までにどれくらいかかるか読めないので、**切り替え予定日の3週間前**
までに出しておく。作業自体は30分程度で終わる内容。

> 件名: 社内システム（マニュアル検索）のMicrosoftアカウント連携について
>
> お世話になっております。アフターメンテナンス課で運用している社内マニュアル
> 検索システムについて、ログイン方式を社員のMicrosoftアカウント（Microsoft 365）
> に変更したいため、Entra IDでの設定をお願いできないでしょうか。
>
> 現在は専用のIDとパスワードを個別に発行していますが、社員が覚えるパスワードを
> 増やさずに済み、退職者のアクセスも人事の手続きだけで止まるため、
> セキュリティ面でも改善になると考えています。
>
> お願いしたい作業は2点です。いずれもM365の契約に含まれる機能で、
> 追加のライセンス費用は発生しません。
>
> **1. アプリの登録（Entra ID）**
> - シングルページアプリケーション（SPA）としてアプリを1つ登録
> - リダイレクトURIの登録（確定後にお伝えします）
> - 社内ユーザーのみがサインインできる設定（シングルテナント）
>
> **2. 通知メールの送信許可（Microsoft Graph）**
> - システムからの通知メール（問い合わせの転送・利用者への案内）を送るため、
>   アプリケーション権限 `Mail.Send` への管理者同意
> - 送信元として使う共有メールボックスを1つ用意（例: `no-reply@…`）
> - この権限は既定ではテナント内の全メールボックスとして送信できてしまうため、
>   Exchange Online の RBAC for Applications で
>   **上記の共有メールボックス1つだけに限定**する設定もお願いしたいです
>
> 現在は外部サービス（Amazon SES）から送っており、社内宛のメールが
> 迷惑メールに振り分けられる問題が起きています。自社ドメインからの送信に
> 変えることで、この問題も解消します。
>
> 不明点があればいつでもご相談ください。よろしくお願いいたします。

## 2. もしIT管理者の対応が間に合わない場合

認証はAWS（Cognito）にあるため、**AWSが閉鎖されると全員ログインできなくなる**。
Entra IDが間に合わない場合は **Supabase Auth**（無料・50,000人まで）で進める。

- メールアドレスと招待でログインする、今と同じ方式
- 追加費用なし、会社への依頼も不要
- 欠点: パスワードを1つ増やすことになる（Entra IDの利点が得られない）
- 後からEntra IDへ移せる

**判断の期限は9月10日**。この時点でIT管理者の作業が始まっていなければ、
Supabase Authで進めて期日を優先する。

## 3. 切り替え当日の手順

詳細なコマンドは [実装ハンドブック](b-plan-implementation-handbook.md) の
「切り替え手順」にある。流れだけ書くと:

1. AWSを読み取り専用の状態にする（アップロードを止める。運用上の周知で足りる）
2. `./scripts/backup-all.sh` で最終データを取得
3. 新環境へデータを流し込む（DB・PDF）
4. 全チャンクの再埋め込み（AIが変わるため必須。一晩）
5. 動作確認（下のチェックリスト）
6. 利用者へ新URLを周知
7. `./scripts/aws-stop.sh` でAWSを停止（**まだ消さない**）

### 動作確認のチェックリスト

- [ ] 会社のMicrosoftアカウントでログインできる
- [ ] キーワード検索でマニュアルが出る
- [ ] AIに質問して、正しいマニュアルを根拠に回答が返る
- [ ] PDFが開ける（PC・スマホの両方）
- [ ] マニュアルをアップロードでき、取り込みが完了する
- [ ] 鍵付きフォルダが一般利用者に見えない（MEMBERアカウントで確認）
- [ ] 管理者のチャット操作（フォルダ作成・移動）が動く
- [ ] 問い合わせを送ると管理者にメールが届く（迷惑メールに入らない）
- [ ] 👍/👎と利用状況の画面が動く

## 4. 撤収前に必ずやること

- `./scripts/backup-all.sh` の最終実行と `./scripts/verify-backup.sh` での確認
- バックアップを2か所以上に保管（会社PC＋外付けドライブなど）
- `infra/` 配下の設定がGitに入っていることの確認
- 撤収の順序は `docs/deployment-plan.md` の撤収手順に従う
